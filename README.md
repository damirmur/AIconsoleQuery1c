# AIКонсольЗапросов1С — внешняя обработка с ИИ для конструктора запросов 1С

Внешняя обработка `ИИ_Консоль_запросов_1С.epf` для платформы `8.3.27` + конфигурация `Бухгалтерия сельскохозяйственного предприятия 3.0.204.22` (типовая + расширения). ИИ помогает писать/чинить запросы 1С на основе живой схемы метаданных, без конфигуратора.

Прокси: `https://astro3d.ru/api/1c-buddy/` (`astro3d.ru:443` → `127.0.0.1:8086` → `https://code.1c.ai` по `ONEC_AI_TOKEN`, `LLM_PROXY_KEY` в `X-API-Key`/`Bearer`/`?api_key=`).

## Что внутри

* **Диалог V2** `compact → NEED → детали + история` stateless `2× POST /v1/chat/completions 200` без `conversation_id` (иначе `404→502`). История хранится локально `ХранилищеОбщихНастроек BuddyHistory + мИсторияБадди:58`, пулинг `manager-1c` отклюён.
* **Кэш метаданных B (только ХранилищеОбщихНастроек)** `AetherAI_MetadataCache.Current` — `СжатыйJSON` (`ХранилищеЗначения + Сжатие9`) вместо `XML` (~150–300КБ vs 1–3МБ), `ВерсииРасширений` только активные, хеш `SHA256(Версия+Метаданные.Версия+ВерсияСловаря+имя:версия)` сортированный. `КэшМетаданных_ОбеспечитьАктуальность()` генерит `СобратьJSONСхему()` напрямую без `ВремФайл.xml`.
* **Словарь сокращений v1** обязательно со схемой:
  * префиксы `Д.=Документ, С.=Справочник, РС.=РегистрСведений, РН.=РегистрНакопления, РБ.=РегистрБухгалтерии, ПВХ.=ПланВидовХарактеристик, П.=Перечисление, БП.=БизнесПроцесс, З.=Задача`
  * типы `С=Строка, Ч=Число, Д=Дата, Б=Булево, ХЗ=ХранилищеЗначения, УИ=УникальныйИдентификатор, Сс=СправочникСсылка, Дс=ДокументСсылка, Пс=ПеречислениеСсылка, ПВХс=…` (`С(100)`, `Ч(10.2)`, `Движения: РБ.Хозрасчетный`)
  * синонимы сохранены `Д.ПутевойЛист (Путевой лист трактора)`
  * `СобратьКраткийКаталог(Истина)` + `ПолучитьДеталиОбъектов(…,Истина)` + `ТекстСловаряДляИИ()` в `system` `ПолучитьКонтекстСхемыКомпакт/Детали`
* **Компакт JSON** `{"v","p","cfg","dict","ext","objs":[{"p":"Д.","n":"…","s":"…","f":[{"n":"…","t":"С(20)"}],"mov":["Регистр…"]}]}` + `Движения` документа для ответа «в какие регистры проводки».
* **Линк сборка** `v8unpack -E/-B` (без `epf-build` — XDTO `2.20 vs 2.17`).

## Диалог / лимиты

* `system` `ПолучитьКонтекстСхемыКомпакт` ~12–16К + `Словарь` + приоритет по ключам запроса + `history` окно `12` по `2000` симв.
* `413 nginx` — режем `26К→16К/18К`, `generic NEED` `РБ.` разворачивается в конкретные `РБ.*` (до 8), `.Модуль` strip, `FALLBACK` на `отсутств/не существует` через локальный `НайтиРелевантныеОбъектыПоЗапросу`.

## Запуск

1. Открыть `ИИ_Консоль_запросов_1С.epf` в `1С:Предприятие 8.3.27` (файловая база `БСП 3.0` + расширения `EF_00_00929336, а7агро, a7agro_obmen, Бюджет`).
2. При открытии — проверка `КэшМетаданных_Актуален()` по хешу. Если пуст/неактуален — `ДаНет` «обновить кэш» → `СобратьJSONСхему()`.
3. Поле `ТокенДоступа` (`LLM_PROXY_KEY`) + `ОтправитьСообщение` → `Buddy_Спросить(ТекстДляБадди, Компакт+Словарь, "", История12)` → при `NEED: Д.Имя` второй вызов с `Детали+Движения`.

Логи: `AetherLog` (`ЗаписьЖурналаРегистрации` на сервере, `Сообщить` на клиенте) + `%TEMP%/aether_debug.log`, `HTTP ENTER/GET/POST` + `ПолучитьКонтекстСхемыКомпакт: длина=… словарь v1`.

## API 1c-buddy

`POST /api/1c-buddy/v1/chat/completions {model:"1c-buddy", messages:[{role,content}], stream, metadata:{conversation_id}}` → `200`, `GET /v1/models` `200`. Ошибки `403` ключ, `500` нет `ONEC_AI_TOKEN`, `502` апстрим `code.1c.ai`, `413` тело.
